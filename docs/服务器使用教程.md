## 1. 第一次开服和进入地图

### 1.1 正确的启动入口

双击：

```text
E:\mapper\chana\ZePractice\run.bat
```

这才是整合跑图服入口。以下两个不是同一个东西：

| 文件 | 用途 |
|---|---|
| `E:\mapper\chana\ZePractice\run.bat` | 新跑图服：预检、挂载地图、加载整合插件、保存日志 |
| `E:\mapper\chana\run.bat` | SteamCMD 更新/验证服务器资源，不是开服 |
| `E:\mapper\chana\steamapps\common\Counter-Strike Global Offensive\game\bin\win64\run.bat` | 之前的旧入口，不作为本教程启动方式 |

不要同时启动两个入口。当前正式入口会先加载内置 `de_dust2`，待它 active 且 RCON 就绪后，自动切到 Workshop 图 `ze_forhidden_slicoo_cn`。短暂出现 `de_dust2` 是启动流程，不是开错图；等最终目标图 active、插件加载成功后再进入游戏。第一次 Workshop 下载可能比以后慢。

当前地图名称为 `ze_forhidden_slicoo_cn`，对应 Workshop 条目 ID 是 `3817448617`；联网自动下载使用第 6.4 节的 Workshop 加载路径。监听 `127.0.0.1:27015` 时仍只开放本机连接，Workshop 地图下载不会自动开放服务器网络端口。

### 1.2 本机进入

在 CS2 设置里开启“启用开发者控制台”，打开游戏控制台，输入：

```text
connect 127.0.0.1:27015
```

进入地图后，在聊天框输入：

```text
!zemenu
!ze_whoami
!ze_status
```

分别是主菜单、自己的身份/权限、当前模式及配置状态。菜单、个人穿墙/检查点需要玩家本人在游戏里使用，不在 Windows 命令行里使用。

### 1.3 每次跑图的推荐顺序

1. 启动上述 `run.bat`，等待地图加载完成。
2. 游戏里 `connect 127.0.0.1:27015`。
3. `!ze_status` 确认是“跑图练习”。
4. `!ze_god` 开个人无敌，`!ze_noclip` 按需要开/关穿墙。
5. 在想重复练习的位置 `!ze_save`；需要回去时 `!ze_tp`。
6. 等门太久时，由服务端控制台临时设置 `host_timescale 2`；练操作前恢复 `host_timescale 1`。
7. 新回合后重新保存检查点；无敌/穿墙先在菜单确认当前状态，不要盲目再次输入开关命令。切图、切模式或重载插件后，再按需要开启辅助。

## 2. 指令应该在哪里输入

这台服务器有四种不同输入位置，前缀也不一样。

| 输入位置 | 示例 | 注意 |
|---|---|---|
| CS2 游戏聊天框 | `!ze_noclip`、`!zeadmin` | `!` 是聊天命令前缀 |
| CS2 客户端控制台 | `css_ze_noclip`、`connect 127.0.0.1:27015` | 自建插件大多数聊天命令对应 `css_` 前缀；仍检查玩家权限 |
| 专用服务器黑色控制台 | `ze_status`、`css_ze_restart`、`host_timescale 2` | 本身具有服务端权限，不加 `!`，也不必再套一层 `rcon` |
| Windows PowerShell | 下方的 `Invoke-ZeRcon.ps1` 调用 | 这是通过 RCON 代替服务器控制台输入，不是把 CS2 指令当 Windows 命令运行 |

两套插件的命令前缀要分清：

```text
自建插件：聊天 !ze_restart   → 控制台 css_ze_restart
自建插件：聊天 !ze_map MAP   → 控制台 css_ze_map MAP
CS2Fixes：聊天 !extend 10    → 控制台 c_extend 10
引擎指令：host_timescale 2   → 服务端直接输入，不加 css_ 或 c_
```

### 2.1 不切到服务器窗口，用 PowerShell 发指令

以下命令读取本机现有密码，不需要把密码写在命令行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\mapper\chana\ZePractice\tools\Invoke-ZeRcon.ps1" -Command "ze_status"
```

把最后的 `"ze_status"` 换成服务端指令即可，例如：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\mapper\chana\ZePractice\tools\Invoke-ZeRcon.ps1" -Command "host_timescale 2"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\mapper\chana\ZePractice\tools\Invoke-ZeRcon.ps1" -Command "host_timescale 1"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\mapper\chana\ZePractice\tools\Invoke-ZeRcon.ps1" -Command "css_ze_restart"
```

RCON 相当于服务端控制台权限；给朋友开插件管理员，不需要把 RCON 密码发给朋友。`server-settings.json` 内含密码，排错时不要整份贴到公开聊天。

## 3. 给朋友添加/撤销管理员

### 3.1 先理解两套权限

- **CounterStrikeSharp / ZePractice 权限**：控制 `!zeadmin`、`!ze_map`、`!ze_ban` 等自建插件命令。
- **CS2Fixes 权限**：控制原生 `!extend`、`!rcon` 等命令。
- 两边互相独立。给其中一边权限，另一边不会自动获得。
- 自建插件的 `OwnerSteamIds` 是服主名单，不要把所有朋友都加成服主。

目前 ZePractice 的管理门槛是 CSS `@css/root`、服主名单或允许的本机回环连接，**还没有按踢人/换图分别细分自建插件权限**。仅授予 `@css/kick` 或 `@css/generic` 不会打开 `!zeadmin`。`@css/root` 也会给其他采用 CSS 权限的插件较广权限，适合真正信任的管理员。

### 3.2 获取朋友的 SteamID64

让朋友进入服务器，在聊天框输入：

```text
!ze_whoami
```

记录显示的完整 SteamID64 数字串，不是昵称、好友代码、个人主页的短网址。若身份是 0 或尚未认证，先处理连接/Steam 身份认证，再授权；不要填一个 0 代替身份。

下文的 `FRIEND_STEAMID64` 必须替换成这个实际数字串，并保留 JSON 双引号。

### 3.3 给 ZePractice 管理权限

编辑前先备份这个文件：

```text
E:\mapper\chana\steamapps\common\Counter-Strike Global Offensive\game\csgo\addons\counterstrikesharp\configs\admins.json
```

保留现有服主条目，在最外层对象里新增一个条目。例如现有对象的最后一项后面加逗号，再加：

```json
"朋友管理": {
  "identity": "FRIEND_STEAMID64",
  "flags": ["@css/root"],
  "immunity": 10
}
```

这是“新增条目片段”，不是用这几行覆盖整个文件。完整结构类似：

```json
{
  "原有服主条目": {
    "identity": "EXISTING_OWNER_STEAMID64",
    "flags": ["@css/root"],
    "immunity": 100
  },
  "朋友管理": {
    "identity": "FRIEND_STEAMID64",
    "flags": ["@css/root"],
    "immunity": 10
  }
}
```

完整例子里的服主信息同样是占位符；实际编辑时保留原有值，不要照抄占位符覆盖。

保存为 UTF-8，然后在**服务端控制台**输入：

```text
css_admins_reload
```

朋友再输入 `!ze_whoami` 与 `!zeadmin` 检查。若仍未刷新，重新连接一次。实际重载命令是 `css_admins_reload`，不是 `css_reloadadmins`。

`immunity` 是管理目标的豁免等级，不是权限开关。本插件额外保护管理员：普通管理员不操作其他管理员；服主名单里的用户或服务端控制台可以处理这些情况。

### 3.4 同时给 CS2Fixes 原生命令权限

另行备份并编辑：

```text
E:\mapper\chana\steamapps\common\Counter-Strike Global Offensive\game\csgo\addons\cs2fixes\configs\admins.jsonc
```

此文件用 SteamID64 作 `Admins` 下的键。保留已有 `Groups`、服主与其他内容，在 `Admins` 中加入：

```json
"FRIEND_STEAMID64": {
  "name": "朋友管理",
  "flags": "bcdefgijk",
  "immunity": 10
}
```

这里的权限包括基础管理、踢人、封禁/解封、处死、换图/延长、配置、聊天和投票，**不含 `m` 的任意 RCON 转发权限**。`z` 是最高权限，不要把普通管理都直接设为 `z`。

保存后，在服务端控制台输入：

```text
c_reload_admins
```

若确实要让朋友在游戏聊天里执行 `!rcon host_timescale 2`，需要该朋友的 CS2Fixes flags 额外有 `m`。加 `m` 意味着可执行任意服务端指令，不只是调倍速；否则由服主在服务端/RCON 工具里操作倍速。

### 3.5 服主名单、本机临时管理与撤权

服主名单在：

```text
E:\mapper\chana\steamapps\common\Counter-Strike Global Offensive\game\csgo\addons\counterstrikesharp\configs\plugins\ZePractice\ZePractice.json
```

- `OwnerSteamIds`：保留现有自己的 SteamID64；仅确需共同服主时再添加。
- `TrustLoopbackAdmin: true`：允许 `127.0.0.1` / `::1` 等纯回环连接获得本插件临时管理，不是所有局域网玩家自动有管。
- 对外开放前建议显式列出管理身份，并设 `TrustLoopbackAdmin: false`，尤其不要用让所有玩家看起来都来自 loopback 的转发方式依赖这个功能。
- 改 `ZePractice.json` 后要重载插件或重启服务器，`!ze_reload` 不重读这个主 JSON。

撤销朋友管理：删除 CSS 管理员条目，执行 `css_admins_reload`；删除 CS2Fixes 对应条目，执行 `c_reload_admins`。如果其身份也在 `OwnerSteamIds`，还要移除并重载插件。完成后重新连接，用 `!ze_whoami` 检查。

## 4. 地图加速、回合时长、延长地图与暂停

### 4.1 想等门快一点：全局时间倍率

在**服务端控制台**逐行输入：

```text
sv_cheats 1
host_timescale 2
host_timescale
```

读回 `host_timescale = 2` 表示已经设成两倍。恢复：

```text
host_timescale 1
```

常用值：`1` 正常，`1.5` 一点五倍，`2` 两倍，`0.5` 半速。先用小倍率，不要直接设极大值。

本机已实际测试 **1 → 2 → 1** 的设置和读回。它改变的是**整个游戏模拟时钟**，不只是某一扇门：移动、物理、Boss 行为及使用游戏时间的计时都可能加快。使用真实时间的脚本/外部计时不保证等比例变化；具体关卡仍要实跑。

当前独立练习 cfg 默认 `sv_cheats 0`，不再从旧通用 cfg 继承开关。先在服务端输入 `sv_cheats` 查询；需要测试受限制的倍率时临时 `sv_cheats 1`，完成后先 `host_timescale 1`，再恢复原来的 `sv_cheats` 值。

拥有 CS2Fixes `m` 或 `z` 权限的人，可以在聊天输入：

```text
!rcon host_timescale 2
!rcon host_timescale 1
```

普通 `!zeadmin` 权限并不自动包含上述原生 `!rcon` 权限。本插件没有 `!ze_timescale`、`!speed` 这样的新命令。

### 4.2 想一回合多跑一会：回合时长

服务端控制台：

```text
mp_roundtime 60
mp_roundtime_defuse 60
mp_roundtime_hostage 60
mp_restartgame 1
```

单位是**分钟**；这三个回合时长参数当前引擎上限都是 60。`mp_restartgame 1` 是 1 秒后重新开始回合，不是把回合设为 1 分钟。

这不会修改地图脚本自己设置的“70 秒后开门”等关卡逻辑，也不是倍速。练习模式忽略常规胜负，但地图自己的触发器、脚本仍可能推进或结束流程。

这些参数是回合时长配置，不是“立刻把当前剩余时间设为 N 分钟”的命令；现有插件也没有 `!ze_roundtime`。FYS 本图配置为 40 分钟，但本轮实测重开后通用 `mp_roundtime=60`、defuse/hostage=40，实际 GameRules.RoundTime=3600 秒。说明后续地图逻辑/配置还有覆盖，尚未定位到具体写入者。修改后应读回三项并观察新回合倒计时，不能仅凭配置文件写40就保证实际40分钟。若需要持久调整，修改 FYS 单图配置后还需排查地图自己的回合时长设置；`0:00`且同时禁止移动/攻击则先看第10.7节，不要反复改时长。

### 4.3 想整张地图多留十分钟：地图总时间

```text
mp_timelimit
c_extend 10
```

或具有 CS2Fixes 地图权限的管理员在聊天中：

```text
!extend 10
```

正数延长，负数缩短，单位分钟。`!timeleft` 查看整张地图剩余时间；它和单回合的时长不是一回事。

**当前跑图练习模式主动把 `mp_timelimit` 和 `mp_maxrounds` 设为 0，并在每回合重申，默认不按这些限制自动换图。** 在练习模式中反复 `!extend` 没必要；临时设置总时长也可能被下一回合覆盖。想换图直接 `!ze_map`。多人 ZE 模式下地图总时长/投票更有意义。

### 4.4 暂停与“跳过倒计时”

- `mp_pause_match` 的本机帮助是**在下一次冻结时间暂停比赛**，不是立即停止当前关卡。跑图模式冻结时间为 0，不适合把它当地图录像式暂停。
- `mp_unpause_match` 恢复比赛暂停。
- 引擎还有 `sv_pausable`、`pause`、`setpause`、`unpause`；本次只核对了存在与帮助，没有对真人客户端验证立即暂停流程，暂不把它们列为已经验证的跑图快捷操作。
- 插件没有通用“只跳过某扇门等待”命令。修改翻译里的 `countdown` 只改变显示的倒计时，不会让门提前开。针对具体地图跳关需要该图实际实体/脚本规则。

## 5. 常用跑图和玩家管理命令

下表默认写的是**游戏聊天输入**；服务端使用自建插件命令时把开头 `!` 改为 `css_`。个人功能仍必须由玩家本人使用。

### 5.1 普通菜单与跑图

| 聊天命令 | 用途/限制 |
|---|---|
