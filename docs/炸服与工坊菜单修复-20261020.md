## 1. 原生炸服根因与修复

核对 2026-10-19 的事件，以及延续至 2026-10-20 凌晨的运行。四份转储均落在：

```text
server.dll + 0xC4B11A
Exception 0xC0000005
RCX = 0x4B0，读取地址 0x540
```

`CTriggerPush` 的共用路径方向 helper 位于 `server.dll+0xFBA620`。它从 `m_PathSimple` 解析句柄，当路径实体失效或已删除时，没有检查 null 就继续访问 path+0x4B0，最终崩溃。`Touch` 和 `StartTouch` 均可进入，不能只改旧推力模式的单一路径。

本次在 CS2Fixes 增加该 helper 的针对性防护：失效路径只令**本次输出方向归零**并跳过原函数；有效路径仍执行引擎原逻辑。不永久关闭地图 path 模式，不改脚本。控制台 `cs2f_push_safety_status` 可查看保护及计数。

已验证：隔离服真实原生调用 7 项检查通过，包含删除路径后 10,000 次陈旧句柄调用，最终 `missing_path_calls=10001`，服务端保持运行。有效路径只验证了句柄可赋值，未将其写成完整运动效果验收。

回装旧原生库的受控复现导致隔离进程退出；由于通过托管探针调用，最终 WER 落在 coreclr，不宣称该 WER 与正式服的 server.dll 地址相同。

## 2. 其他玩家没有右侧菜单

在正常启用 Workshop 指令过滤的真实游戏客户端复现旧包报错：

```text
WORKSHOP COMMAND: css_ze_select does not exist, ignoring
```

旧资源中的无线电表直接执行服务端注册的 `css_ze_*`，客户端将其视为不存在的本地命令并拦截。本机历史上设置过 `-disable_workshop_command_filtering`，不能用本机旧表现代表其他客户端。

修复分三处：

1. 工坊无线电表改用客户端已有的 `say !ze_*`，不要求玩家关闭工坊命令过滤，不追加 `-addon` / `-tools` 或全局 VPK 搜索路径。
2. 服务端明确接管本插件已注册的 `!命令`、`/命令`、`！命令`。保留原始玩家身份与权限入口，不提升为控制台/RCON，不抢占其他插件或普通聊天；避免重复动作。
3. 保留 `say !ze_select 8` 这种未加引号指令的全部参数，修复旧代码只读第一个参数而丢失按键值的问题。

另外修复三个 HUD 服务预缓存传入编译文件名的错误：`AddResource` 使用逻辑 `.vxml/.vcss`，而 VPK 校验清单及已验证的实体 layout 继续使用 `.vxml_c/.vcss_c`。不制作虚假的 `_c_c` 文件。最终重新预缓存、真人重连后的日志，六类 HUD 双后缀请求计数为 0。
