## 2. 聊天、客户端控制台、服务端控制台，不是一回事

| 位置 | 正确例子 | 说明 |
|---|---|---|
| 游戏内聊天 | `!ze_save`、`！ze_save` | 本插件支持半角 `!`，也处理全角 `！` |
| 玩家自己的开发者控制台 | `css_ze_save` | 不写 `!`，也不要把正常玩家指令套进 RCON |
| 玩家自己的按键绑定 | `bind "INS" "css_ze_save"` | 按键仍以本人身份执行，权限不会提高 |
| 服务器控制台 / 已认证 RCON | `css_ze_restart`、`host_timescale 2` | 服务端身份拥有本插件最高权限；需要玩家实体的功能仍要玩家本人进服 |
| CS2Fixes 原生命令 | 聊天 `!map 3817448617`；控制台 `c_map 3817448617` | **`c_`，不是 `css_`**；使用另一套管理员 flags |
| 引擎 ConVar/命令 | `mp_roundtime 60`、`host_timescale 1` | 不加 `css_` 或 `c_` |

### 2.1 同一功能的三种写法

```text
聊天：!ze_noclip
聊天：！ze_noclip
客户端控制台：css_ze_noclip
```

菜单按钮、快捷键和直接指令都会重查同一操作权限。把 `css_ze_noclip` 绑定到别的按键、用全角感叹号或换一个别名，都不会绕过权限。

### 2.2 全角命令的范围与参数

- 全角 `！` 由本插件桥接到当前已注册指令；普通半角命令仍由框架/原插件处理。
- 输入一条命令；不要把多个动作写成带分号的聊天“脚本”。本插件桥接不接收分号、控制字符、反斜杠或不成对的双引号。
- `！1`～`！9` 可用于聊天菜单数字选择，半角 `!1`～`!9` 同样可用。
- 原生 CS2Fixes 只有桥接白名单中且确实注册的部分命令支持全角；**原生命令不确定时用半角 `!`，或直接 `c_命令`**。
- 带空格的名字可使用双引号，但管理玩家优先使用 `#userid`，例如 `!ze_kick #12`，避免同名匹配。

### 2.3 目标写法

本插件的管理/传送目标支持：

```text
#12
玩家完整名称
唯一的一段名字
玩家的17位SteamID64
@me
```

`#12` 是本次连接的 UserID，不是 SteamID、玩家槽位或队伍编号。重连后可能变化。名字匹配多人时插件拒绝任选一个，不会随便处罚第一人。`@me` 仅代表执行命令的玩家，服务端控制台没有“自己”的玩家实体。

## 3. 快捷键：按键做什么，以及怎么自己改

### 3.1 本次安排

| 按键 | 本插件动作 | 控制台命令 |
|---|---|---|
| ALT | 切换自己的穿墙 | `css_ze_noclip` |
| F9 | 打开/关闭主面板 | `css_ze_ui` |
| F11 | 切换自己的无敌 | `css_ze_god` |
| INS | 保存检查点 | `css_ze_save` |
| HOME | 返回检查点 | `css_ze_tp` |
| END | **只删除检查点** | `css_ze_clearcheckpoint` |

先在自己的客户端控制台查询原绑定，再决定覆盖：

```text
bind ALT
bind F9
bind F11
bind INS
bind HOME
bind END
```

需要手动配置时，在**玩家自己的客户端控制台**逐行执行：

```text
bind "ALT" "css_ze_noclip"
bind "F9" "css_ze_ui"
bind "F11" "css_ze_god"
bind "INS" "css_ze_save"
bind "HOME" "css_ze_tp"
bind "END" "css_ze_clearcheckpoint"
```

也可以把以上内容保存到自己的 CS2 cfg 文件，再 `exec`。本机客户端 cfg 目录：

```text
D:\SteamLibrary\steamapps\common\Counter-Strike Global Offensive 730\game\csgo\cfg
```

如客户端已部署 `ze_practice_keys.cfg`，执行：

```text
exec ze_practice_keys
```

朋友的安装盘符可能不同，且服务器上的 cfg 不等于朋友电脑上已经有该文件。如果提示文件不存在，直接使用上面的六条 `bind`，无需先复制整个服务器目录。

### 3.2 F5 / F7 / F8 保留原 FYS 用途

已有 FYS 绑定语义是：

| 原键 | 原命令 | 原用途 |
|---|---|---|
| F5 | `ms_tp` | FYS 第三人称 |
| F7 | `ms_c` | FYS 上指挥 |
| F8 | `ms_dc` | FYS 卸指挥 |

**本插件不把这些改成回点、存点、删点。** 因此不能把 F5 当本服回点键，也不要用 `ms_*` 去配置本插件权限。

保留原绑定不等于本服自动具有 FYS 私有 `ms_*` 功能：只有相应服务器实现这些命令时，原用途才生效。回点用 HOME，存点用 INS，删点用 END。

### 3.3 关闭卡住的面板

优先在客户端控制台输入：

```text
css_ze_ui_close
```

需要改回聊天菜单：

```text
css_ze_ui_chat
```

`css_ze_ui_close` 是释放鼠标的恢复入口，不因撤销普通菜单权限而阻止关闭。关闭面板不会踢出玩家、关闭服务器，也不会修改玩家的移动类型或无敌状态。

## 4. 角色说明：下面命令表怎样读

| 缩写 | 默认角色 | 用途 |
|---|---|---|
| P | `player` | 主菜单、状态、枪械/职业/Boss HUD/神器查询等公共操作 |
| R | `practicer` | 继承 P；个人跑图辅助和自由补给 |
| M | `moderator` | 继承 P；踢人、禁言、换队等日常管理；豁免 10 |
| A | `admin` | 继承 R＋M；本插件常规管理、地图、Boss/神器诊断；豁免 50 |
| O | 真实最高权限 | 服务端/RCON、认证服主、配置允许的可信回环、启用绕过时的 CSS root |

默认 `DefaultRoles` 为 `player`＋`practicer`，所以正常进服者默认能跑图；M/A 要手动分配。**Users 里分配角色是叠加，不是替换 DefaultRoles。** 下表列的是提供该许可的最低默认角色，不表示给了 M 就会失去公共 R。

同样，管理员角色的名称和数字本身没有魔法：叫“超管”、Immunity 写 999，也不自动获得任何 Allow 中没有的指令。

### 5.2 个人跑图辅助

下列自助动作除复活的特殊说明外，需要真人玩家进入服务器，且 `PracticeMode=true`。**服主身份也不代表在多人 ZE 模式中启用练习辅助。**

| 聊天用法 | 准确权限键 | 默认 | 实际行为 |
|---|---|---|---|
| `!ze_god` | `css_ze_god` | R | 切换个人无敌；需存活。防伤害，不保证阻止地图直接删人/强制传送 |
| `!ze_noclip` | `css_ze_noclip` | 全员 | 切换个人穿墙；需存活，不受练习模式/角色限制 |
| `!ze_save` | `css_ze_save` | R | 保存当前位置/朝向为当前地图当前回合检查点 |
| `!ze_tp` | `css_ze_tp` | R | 返回自己的有效检查点；需存活 |
| `!ze_clearcheckpoint` | `css_ze_clearcheckpoint` | R | **只删检查点，不关闭无敌/穿墙** |
| `!ze_reset` | `css_ze_reset` | R | 清除自己的无敌、穿墙和检查点 |
| `!ze_respawn` | `css_ze_respawn` | R | 请求自己复活；已活着则不重复复活，观察者自助复活会请求切到 CT |
| `!ze_goto <目标>` | `css_ze_goto` | R | 把自己移到指定在线玩家身边；双方需要存活 |
| `!zerefill` | `css_zerefill` | R | 补满生命和地图出生补给；练习菜单有对应按钮；不清空本回合普通购买次数 |

操作例子：

```text
!ze_save
!ze_noclip
!ze_tp
!ze_clearcheckpoint
```

- 检查点在新回合或切图时清空，不能跨关卡/旧回合使用。
- 无敌权限撤销时恢复对应状态；1.2.0 穿墙为明确公开命令，不通过角色 Deny 撤销，玩家可自行关闭。
- 撤销存点或回点权限会清除已有检查点，避免旧状态继续被使用。
- 自动复活不仅取决于 `AutoRespawn`，还需要当前玩家有 `css_ze_respawn`，且处于练习模式、不是观察者；延时到期仍会重新检查。
- 旧控制台 `noclip`、`god` 在本服被桥接到对应个人练习动作；推荐绑定明确的 `css_ze_noclip`、`css_ze_god`。

处罚分钟：**0～525600 的整数；`0` 是永久，不是取消**。省略原因时使用“管理员操作”。示例：

```text

!ze_mute #12 30 连续刷麦
!ze_gag #12 10 刷屏
!ze_ban #12 60 管理处理
!ze_team #12 ct
!ze_respawn_other #12
```

`!ze_respawn <目标>` 兼容旧写法：基础命令入口先检查 `css_ze_respawn`，当目标不是自己时，还检查 `css_ze_respawn_other`。只想授予“复活他人”的角色，使用独立的 `!ze_respawn_other` 最清楚。

处罚系统仅管理自己的记录：`!ze_unban` 不会替 CS2Fixes 或其他插件解除封禁；本插件解禁后仍有其他插件处罚，需要分别处理。

玩家管理菜单会再次核对操作权限、目标 Slot/UserID 和豁免。踢出、处死、封禁等危险按钮保留确认；打开菜单后撤权，旧按钮也不会继续生效。

## 6. 如何给朋友上管理：推荐用自定义角色

### 6.1 确认朋友身份

1. 朋友正常进服，在聊天输入 `!ze_whoami`。
2. 等显示 Steam 身份已认证，取得其 **17 位 SteamID64**。
3. 服主备份运行中的 `data\permissions.json`。
4. 在该文件现有 `Users` 对象中增加条目，不删除已有用户。

仅举结构例子，下面 `FRIEND_STEAMID64` 必须换成朋友实际的 17 位数字；**占位符原样保存会导致校验失败**：

```json
"Users": {
  "FRIEND_STEAMID64": ["moderator"]
}
```

- 日常踢人、禁言、换队：`moderator`。
- 需要换图、重开回合、Boss/神器诊断：`admin`。
- 只想开放两三项动作：自定义一个新角色，见 6.3。
- 不要为了普通管理就加 `OwnerSteamIds` 或 CSS `@css/root`，否则该用户按最高权限绕过普通角色 Deny，分级就失去作用。

### 6.2 保存并热重载

由服主在聊天执行：

```text
!ze_permissions_reload
```

或者在服务器控制台执行：

```text
css_ze_permissions_reload
```

看到成功提示后，朋友重新执行 `!ze_whoami`、`!ze_commands`、`!zeadmin`。

角色热重载不要求朋友重连；菜单会重新受权限约束，打开的图形会话关闭，练习辅助立即复核。另有每秒复核兜底，延时复活也会在真正执行前复查权限。

**`!ze_reload` 不是权限重载。** 把 JSON 保存到磁盘后只执行 `!ze_reload`，不会更新角色。

### 6.3 自定义任意名称/等级，例如“地图助教”

在现有 `Roles` 内增加这个角色对象，保留其他角色：

```json
"地图助教": {
  "Inherits": ["player"],
  "Immunity": 20,
  "Allow": [
    "css_zeadmin",
    "css_ze_adminhelp",
    "css_ze_map",
    "css_ze_restart",
    "css_bossstatus"
  ],
  "Deny": [
    "css_ze_ban",
    "css_ze_permissions_reload"
  ]
}
```

然后把朋友的 Users 值设为：

```json
["地图助教"]
```

它可以打开管理菜单、换图、重开回合、查 Boss，但未允许的踢人/封禁不会因为 Immunity=20 而自动开放。还会叠加全服 DefaultRoles；如果希望该朋友不使用全服默认跑图功能，需要添加明确 Deny 或调整 DefaultRoles，而不是以为新 Users 条目替换默认权限。

**给一个管理动作，通常也给相应导航入口。** 例如要让“地图助教”用图形管理菜单，至少需要 `css_ze`、`css_zeadmin` 和具体操作键；继承 `player` 已包含 `css_ze`。单纯允许 `css_ze_map` 时，直接命令可以工作，但不代表所有菜单都开放。

### 6.4 Allow / Deny / Inherits 的真实规则

- `Allow` 支持准确指令名：`css_ze_kick`。
- 支持末尾前缀通配：`css_ze_*`、`css_boss*`、`css_*`。
- `"*"` 表示所有正常命令许可；不是角色名称，也不把用户变成真实 Owner。
- 不支持正则表达式或中间星号；`css_*_kick`、`.*` 不是合法规则。
- 命令名统一到 canonical 后匹配，忽略大小写。
- **任何有效角色的 Deny 都优先于任何 Allow**，包括继承角色、默认角色和多个 Users 角色之间。
- 因此，“给另一个角色加 Allow”不能覆盖已有 Deny。
- 角色继承不允许循环；被引用的角色必须存在。
- Roles/Users 等 JSON 属性名按模板准确拼写；拼写错误不是静默忽略。
- 不要把参数写进权限：写 `css_ze_map`，不是 `css_ze_map de_dust2`。

注意通配边界：

```text
css_ze_*  会匹配 css_ze_map、css_ze_god
css_ze_*  不匹配 css_zeadmin、css_zebuy、css_zerefill
css_ze*   会匹配以上所有 css_ze 开头名称
```

普通 `admin` 默认使用 `css_ze*` 等 Allow，但显式 Deny `css_ze_permissions*`、`css_ze_root*`，因此**默认 admin 不是服主，不自动允许权限重载**。

### 6.5 将权限重载委派给专门角色

服主如果确实要委派，可以创建：

```json
"权限维护": {
  "Inherits": ["player"],
  "Immunity": 60,
  "Allow": ["css_ze_permissions_reload"],
  "Deny": []
}
```

但如果这个用户同时继承或被分配默认 `admin`，其 `css_ze_permissions*` Deny 仍会生效。要么不把两个角色组合，要么服主明确修改那条 Deny；单独提高 Immunity 没用。

重载权只允许加载服务器已经存在的权限文件，并不直接给游戏内玩家写磁盘权限文件的功能。不要将这个键误解成可在聊天任意编辑 JSON。

### 6.6 DefaultRoles 与公共跑图开关

默认：

```json
"DefaultRoles": ["player", "practicer"]
```

主插件 JSON 的：

```json
"AllowEveryonePracticeCommands": false
```

会去掉默认 `practicer`，并阻止仅由默认角色授予的自助练习动作。**显式 Users 角色授予仍然有效**，便于只给指定朋友跑图辅助。已有 Deny 仍优先。

修改 `AllowEveryonePracticeCommands` 属于主插件配置变更，需要按主 JSON 的加载方式重载插件或重开服务；`!ze_permissions_reload` 只读取角色文件，不顺带读取主 JSON。

### 6.7 豁免等级与最高权限

普通角色的 `Immunity` 允许 0～1000000。实际目标保护使用：

```text
max(有效角色的最高 Immunity, 已认证 CSS 管理员的 Immunity)
```

- 高等级目标不能被低等级操作。
- 同级受保护管理员不互相处罚。
- 同级且正豁免的受保护目标也会被保护。
- 更高等级管理员可以操作较低等级管理目标。
- 服主/服务端最高权限可越过普通目标保护。
- 自己操作自己仍要有具体动作权限；豁免不是授予命令许可。

最高权限来源只有：

1. 服务端控制台/已认证 RCON。
2. 主 JSON `OwnerSteamIds` 内匹配的已认证 SteamID64。
3. `TrustLoopbackAdmin=true` 时可信的纯数字本机回环连接。
4. 权限文件 `CssRootBypass=true` 时，已认证 CSS `@css/root`。

角色起名为 `owner`、Allow 写 `*`，都不会让目标判定的 `IsOwner` 自动为真。相反，已经是 Owner 的人不会被普通角色 Deny 限制。测试限权效果时，不要用自己的 loopback 最高权限连接当普通玩家结论。

### 6.8 撤权与坏文件处理

撤销一个朋友：从 Users 删除其条目，或缩减角色 Allow/添加 Deny，然后 `!ze_permissions_reload`。

如果仍显示最高权限，继续检查该身份是否在 `OwnerSteamIds`、CSS root 或可信回环中；只删除 Users 并不会删除这些独立最高权限来源。

格式错误、未知角色、循环继承、坏 UTF-8、文件超过 256 KiB 等会使热重载失败，**保留上一份有效权限，不会把大家误变成管理员，也不会把坏文件偷偷覆盖成默认配置**。根据报错修好文件，再重载；不要把“重载失败”当成撤权成功。

## 7. 时间加速、回合时间和地图时间：分清三种需求

**当前实际注册中没有 `!ze_timescale`、`!ze_roundtime`、`!ze_time`。** 即使在权限文件里写入这些名字，也不会凭空新增命令。下面使用确实存在的引擎/原生入口。

### 7.1 等门快一点：全局倍速

在**服务端控制台**逐行执行：

```text
sv_cheats
host_timescale
sv_cheats 1
host_timescale 2
host_timescale
```

恢复：

```text
host_timescale 1
```

完成后把 `sv_cheats` 恢复到此前查询到的状态。本服独立练习 cfg 的默认值不应靠旧全局 server.cfg 猜测，以实际读回为准。

`host_timescale` 改变全局游戏模拟时间，不是只加速某扇门。移动、物理、Boss 和使用游戏时钟的脚本都可能受影响；真实时间计时器不保证同速变化。

有 CS2Fixes `m`/`z` 权限时，可以用其独立聊天 RCON：

```text
!rcon host_timescale 2
!rcon host_timescale 1
```

本插件 `admin` 角色不自动授予原生 `!rcon`。`m` 是任意服务端指令转发，不只是“调时间”按钮。

### 7.2 下一个回合更长

服务端查询/设置：

```text
mp_roundtime
mp_roundtime_defuse
mp_roundtime_hostage
mp_roundtime 60
mp_roundtime_defuse 60
mp_roundtime_hostage 60
css_ze_restart
```

这些值以分钟计，分别关联不同规则。它们不是精准设置**当前回合剩余秒数**的通用接口，也不保证输入后 HUD 立刻跳到新值。地图/FYS 配置或回合逻辑还可能重新写值；重开后再读回确认。

### 7.3 延长当前地图，不是延长本回合

CS2Fixes 的：

```text
!extend 10
```

或控制台：

```text
c_extend 10
```

是延长地图时间，要求 CS2Fixes `g`/`z`。负值会缩短时间，不是普通跑图的回合重启。

当前练习模式会应用不限地图时间/无限回合配置（例如 `mp_timelimit 0`、`mp_maxrounds 0`）。这时没有必要不断延长地图；`!timeleft` 显示与多人有期限模式不同是正常的。

若红色 `0:00` 且不能移动，不要只不断增加 roundtime：先 `css_ze_ui_close` 排除面板输入捕获，再按原教程检查冻结/中场状态、当前 profile 与日志。不要在 Workshop 地图中随便 `exec server` 混入旧全局配置。

### 8.1 两个命令看起来相似，实际上不同

|---|---|
| `!ze_kick` / `css_ze_kick` | `!kick` / `c_kick` |
| `!ze_ban` / `css_ze_ban` | `!ban` / `c_ban` |
| `!ze_mute` / `css_ze_mute` | `!mute` / `c_mute` |
| `!ze_map 地图名` / `css_ze_map 地图名` | `!map WorkshopID` / `c_map WorkshopID` |
| `!ze_permissions_reload` | 管理员 JSON 重读用 `c_reload_admins` |

改 `permissions.json` 只管理本插件域，**不会重写 CS2Fixes 原生 flags**；也不自动改变 CSS 其他插件权限。服务器/RCON 是另一个明确的高权限执行入口，不能与普通玩家指令混用来测试限权。

### 8.2 本机 CS2Fixes 提交的几个常用 flags

以下按已安装源码提交 `bb3be34` 的注册核对，不凭 flags 名称猜测：

| 原生命令 | 必要 flag（或 `z`） |
|---|---|
| `!kick` | `c` |
| `!ban` | `d` |
| `!unban` | **此提交注册使用 `d`**，不要只因字母 `e` 名为 UNBAN 就假定该指令用 `e` |
| `!slay` / `!goto` / `!bring` | `f` |
| `!map` / `!extend` | `g` |
| `!mute` / `!unmute` / `!gag` / `!ungag` | `j` |
| `!rcon` | `m` |
| 原生 `!noclip [目标]` | `n`；与本插件自助 `!ze_noclip` 不同 |
| 最高管理 | `z` |

如果只想让朋友管理本插件，优先使用第 6 节，不需要同时给原生 `m` 或 `z`。

修改原生 admins.jsonc 后，在服务器控制台执行：

```text
c_reload_admins
```

修改 CSS admins.json 后，实际命令是：

```text
css_admins_reload
```

不是 `css_reloadadmins`。CSS `@css/root` 在 `CssRootBypass=true` 时也会绕过本插件普通角色限制；普通 CSS `@css/kick` 不等于自动获本插件 `css_ze_kick`。

## 9. 图形 UI、鼠标与远程资源

### 9.1 默认采用什么界面

主插件有：

```json
"MenuUiMode": "panorama",
"MenuAssetsReady": false,
"PanoramaAllowRemoteClients": false
```

这是源码默认值示意，不代表部署后已验证为哪个值。应以实际主插件 JSON 和验收记录为准。

图形布局与样式编译后分别需要：

```text
panorama/layout/custom_game/zepractice/main.vxml_c
panorama/styles/custom_game/zepractice/main.vcss_c
```

源码分别为本项目 `panorama/layout/custom_game/zepractice/main.xml` 与 `panorama/styles/custom_game/zepractice/main.css`。仅把 XML/CSS 放到服务器目录，不等于客户端已有可加载的编译资源。

### 9.2 正常交互与回退

- `!ze` 或 F9 打开菜单，菜单里实际操作仍检查本人权限。
- 灰色按钮表示当前不可执行；不是点得够快就能生效。
- 管理员可用 `!ze_ui_status` 或 `css_ze_ui_status` 读面板诊断；计数/实体创建只是服务端证据，不证明客户端已看见图形。
- 首次会话有约 **20 秒**的可见性/点击确认窗口；未确认会自动释放鼠标并回退聊天菜单。
- 已确认会话约 **2 分钟**无操作自动关闭，释放鼠标。
- 远程会话在确认资源可见前不应依靠强制抓鼠标；确实看见完整面板后 `!ze_ui_ready`。
- 本机已验证资源时可以启用捕获，但仍保留首次确认超时恢复。
- 任何时候优先 `css_ze_ui_close` 退出；想固定使用聊天菜单，`css_ze_ui_chat`。
- 从聊天模式重新尝试时：先 `!ze_ui_ready` 清除本次连接的聊天偏好，再 `!ze`；看见面板后再次确认。
- 权限重载会关掉旧图形会话，避免旧按钮状态误导；重新打开获取新菜单。

图形面板捕获的是 UI 输入，不应改变角色 MoveType、Velocity、God 等玩家状态；个人辅助使用单独动作来修改和恢复。

### 9.3 为什么自己能看见，朋友不一定能看见

服务器上的编译资源仅证明服务端有文件，不能证明朋友的游戏客户端已下载/挂载它们。本图 Workshop 条目是 **3817448617 / ze_forhidden_slicoo_cn**，地图自动下载与 UI 自动分发是相关但不相同的事情：

1. 只有实际发布进朋友会下载/挂载的地图或资源 addon 的文件，朋友才会拿到。
2. 服务器后来新增 UI 松散文件，不会自动更新已经发布的 Workshop 地图。
3. 独立资源 addon 需要明确真实条目与挂载/分发方案，不是填一个虚构 ID。
4. UI 资源不就绪时使用聊天菜单，跑图、权限和普通命令仍可用。
5. 不要只把 `PanoramaAllowRemoteClients` 改 true 就声称已完成分发；也不要在朋友看不见界面时让其盲目确认鼠标捕获。

本手册不把“源码编译成功”“服务端能创建 UI 实体”当作“所有朋友都看见并点击成功”。实际验收需要可见截图、真实按钮响应与关闭后鼠标恢复，尤其是远程客户端。

## 10. 常见问题与最短排查

| 现象 | 先检查 |
|---|---|
| 按 ALT 没反应 | 客户端 `bind ALT` 是否正确；是否练习模式/存活；`!ze_whoami` 与 `!ze_commands noclip` |
| F5/F7/F8 不按本服存点/回点 | 这是刻意保留原 FYS 语义，本服使用 INS/HOME/END |
| `Unknown command: ms_c` | 本服不伪造 FYS 私有命令；按本服 INS 存点 |
| `!ze_tp` 说没有存点 | 先存活时 `!ze_save`；是否已切图/新回合/撤销 save 或 tp 权限 |
| END 后无敌还开着 | 正常：END 只删点。要关闭全部用 `!ze_reset` |
| 给了 admin 但不能权限重载 | 默认 admin 显式 Deny `css_ze_permissions*`；这是预期，服主执行或按 6.5 委派 |
| 改 Users 后朋友仍没有管理 | 改的是运行文件吗？执行的是 `!ze_permissions_reload` 吗？是否成功？ID 已认证吗？角色是否真实存在？ |
| 加了角色 Allow 仍被拒 | 默认/继承/另一个角色是否有 Deny；命令权限写的是 canonical 吗？ |
| 降权自己仍什么都能做 | 自己是否 Owner/CSS root/可信 loopback；这些是最高权限来源 |
| 能进管理菜单，封禁按钮灰色 | 菜单许可不等于封禁许可；moderator 默认没有 `css_ze_ban` |
| 能复活别人，不能复活自己 | 自助 `css_ze_respawn` 与管理 `css_ze_respawn_other` 是独立许可 |
| 只有原生 `!map` 被拒 | 原生 CS2Fixes `g`/`z` 与本插件角色独立 |
| `!bossstatus` 没权限 | 此命令是管理实体诊断；普通 Boss HUD 用 `!bosshud` |
| 地图/Boss参数改了没生效 | `!ze_reload` 只覆盖相应重载范围；实体修补常需重载地图；实际值要读回 |
| 鼠标被菜单占用但没图形 | 客户端 `css_ze_ui_close`，再 `css_ze_ui_chat`；检查编译资源与分发，不猜已可见 |
| 朋友进不来 | 先地址/监听/网络/Workshop下载；角色 JSON 不负责网络连通 |
| 全角命令报格式不对 | 一次一条命令；不要分号、反斜杠、不成对引号；原生命令改用半角或 c_ |
| 重载坏 JSON 后旧管理员仍有管 | 失败保留 last-good 属于设计；修好并确认重载成功再验撤权 |

## 11. 修改完后的验收清单

建议用一个**不在 Owner/CSS root/可信回环绕过范围内的测试玩家**确认分级，而不是只用服主本人。

1. `!ze_whoami` 显示预期角色与豁免。
2. `!ze_commands` 不列未授权的业务动作。
3. 同一命令的聊天、全角、客户端控制台、快捷键、菜单按钮结果一致。
4. “只踢人”角色能踢普通目标，但不能处死、封禁或换图。
5. 低豁免不能管理高豁免，同级受保护管理员不互相处罚。
6. 打开旧菜单后撤权并重载，原按钮也不能继续执行。
7. 开启无敌和穿墙后，只撤销无敌，角色重新可受伤，但仍保持合法穿墙；再撤穿墙能恢复原移动状态。
8. END 只清存点，不改变其他辅助；新回合/切图不沿用旧存点。
9. 死亡等待复活期间撤销 `css_ze_respawn`，延时回调不再复活。
10. 图形界面关闭后鼠标恢复；资源缺失时聊天回退可操作。
11. 远程朋友另行确认资源下载、界面可见与按钮成功，不能只用本机结果代替。

本次源码回归覆盖精确动作权限、Deny/继承、认证身份、菜单与目标重连、辅助撤销、延时复活等；这些是自动化测试证据，不替代上述真实游戏内验收。
