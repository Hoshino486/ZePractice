# 服主直接换图导致地图服务停止：1.7.11 修复记录

日期：2026-10-20（Asia/Shanghai）。

## 已确认的原因

正式服在 **15:00:38–15:00:39** 从 `ze_forhidden_slicoo_cn` 直切 `ze_overkill_p`（Workshop `3799577772`）时：

```text
Failed to mount world vpk file maps\ze_overkill_p.vpk, file could not be found.
NETWORK_DISCONNECT_CLIENT_NO_MAP
Server shutting down: NETWORK_DISCONNECT_CLIENT_NO_MAP (64)
```

这次是目标世界加载失败后服务器地图服务关闭，不是已证实的 CS2Fixes 原生崩溃；没有与这次事件对应的新崩溃转储。旧代码生成 `map ze_overkill_p customgamemode=3799577772 nomapvalidation=true`，跳过了引擎的工坊准备流程，只根据缓存目录中存在 VPK 就先卸载旧图。

在隔离服复现了完全相同的 NO_MAP 错误。走 `host_workshop_map` 完成工坊下载/登记后，这张图进入 `ss_active`。重新下载的四个 VPK 与正式服原有四个 VPK 的 SHA256 **全部一致**，没有通过替换地图内容或改地图脚本解决问题。

## 修复内容

- ZePractice 升级为 **1.7.11**。
- MultiAddonManager 升级为 **v1.6.2-0-gd6b4f4b-saibochana.20261020-mapload**。
- 按地图名直切改为：请求工坊准备 → 验证目标 addon 内的指定地图 → 由引擎提交换图。
- 用独立且 request-only 的临时搜索路径检查目标地图，避免把当前地图或其他 addon 的同名文件误当成目标文件；检查后立即移除搜索路径。
- 同一工坊包有多张地图时，保留选择的实际 VPK 地图名，不悄悄切换到默认图。
- 缺包、地图不存在、原生桥未加载时不提交危险的直接 `map` 命令。
- 为每次请求分配唯一 token；下载失败、超时、插件卸载、地图会话变化时撤销旧请求。被取消请求的延迟完成事件不会再触发换图。
- 保留服主权限、RTV 严格超过 80%、每图清空候选、Bot 阵营选择和编号传送逻辑。

## 使用方式不变

服主菜单中选择已下载地图，或者聊天输入：

```text
!ze_map ze_overkill_p.vpk
```

服主按工坊 ID 立即加载仍是：

```text
!ze_workshop_now 3799577772
```

普通玩家聊天中的 `host_workshop_map +ID` 仍然只添加候选，不会直接切图。工坊需要下载时留在当前图等待；下载失败或超时会提示重试。客户端不需要新增启动项，也不需要重新发布资源包。
