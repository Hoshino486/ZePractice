## 两个问题及修复

### 1. 数字变成竖条、方块或横向错位

不是工坊未批准，也不是10秒倒计时计算错误。原OBJ坐标与最终ModelDoc编译坐标不同：

| 方向 | 原OBJ | 实际工坊编译模型 |
|---|---|---|
| 向上 | +Z | +X |
| 正面 | +X | +Y |
| 文字向右 | +Y | +Z |

实际资源的转换为 `compiled(x,y,z) = source(z,x,y)`。从服务器已安装VPK提取数字8后得到边界 `(0,-1.5,-12)` 至 `(48,1.5,12)`，不是48单位高的Z轴模型。

旧插件仅设置 `(pitch=0, yaw=facingYaw, roll=0)`，导致模型侧面对着玩家。数字8的投影宽度仅3单位；数字1的投影宽度3、高度5，正好对应截图中的竖条与方块。

现在按实际编译轴向设置：

```csharp
CommanderCountdownLayout.ModelAngles(facingYaw)
// (-90, facingYaw - 90, 0)
```

编译+X转为世界竖直向上，+Y朝向查看者，+Z沿查看者画面从左至右。保留每名玩家独立朝向、原有居中排列和数字换位实体复用。没有重新生成或修改数字资源。

### 2. 热重载丢失模型就绪状态

1.7.4部署后的验收发现：正式地图原本已加载数字模型，但CSS热重载不再次触发地图资源预缓存回调。新CommanderService回到 `awaiting-map-precache`，退回普通文字。因此首次1.7.4没有作为完成结果交付。

1.7.5增加热加载恢复：

1. 校验服务器实际安装VPK中的10个数字及材质/贴图成员、长度和CRC。
2. 在游戏线程中用不可见、无碰撞、同回调清理的临时实体检查当前引擎真正解析到的10个模型。
3. 同时检查模型名称、非零资源句柄及实际编译边界，避免把error模型误认为有效模型。
4. 全部通过才恢复模型数字；不下载、不重新挂载工坊、不调用失效的预缓存manifest、不重启或换图。
