# 远端右侧菜单与关闭修复 — ZePractice 1.7.7

日期：2026-10-18。范围：远端客户端菜单不出现、打开后关闭不一致。

## 根因与修复

1. 正式配置为 `MenuUiMode=radio`、`MenuAssetsReady=true`，但 `PanoramaAllowRemoteClients=false`。原代码因此直接拒绝远端玩家创建右侧面板；异常只输出提示，没有可操作回退。已将正式配置的该项开启。不是地图脚本或工坊审核问题。
2. `css_ze_ui` 原来只判断鼠标 Panorama 服务，遗漏现服 Radio 服务和下一帧待打开状态。现在同时识别 Radio、Panorama、聊天菜单以及待打开请求；再次输入会关闭，不会叠加重开。主菜单处理器保留原始调用玩家和权限。
3. 统一 `css_ze_ui_close`、`css_ze_select 0/9`、聊天 `!0/!9` 的关闭行为。关闭本身不受普通操作权限阻挡；正常操作与重新打开仍校验权限。关闭取消待打开、待选择及待刷新任务，不恢复已经关闭或替换的旧菜单。
4. `!1`–`!8` 和全角叹号数字会路由至当前菜单，而不是错误地发给聊天渲染器。实际回退为聊天菜单时，即使全局配置仍为 radio，仍然能够使用。
5. 每位玩家的 Radio 实体只向本人发送；补充 CheckTransmit 本人强制传输和其他接收者剔除，保持全局隐藏/本人可见状态。连接身份校验包含 slot、userid 和 controller serial。
6. 检查正式安装的工坊 VPK 中 radio 布局、样式和无线电输入表的 CRC；资源/配置不就绪、实体创建或刷新失败时，提供实际聊天菜单回退。`!ze_ui_chat` 可手动切换，本连接后续打开也遵从该选择；`!ze_ui_ready` 恢复图形菜单。
7. `!ze_ui_status` 使用普通菜单权限，玩家只看到自己的会话明细；控制台仍可查看全部会话。

## 玩家使用

| 位置 | 输入 | 行为 |
|---|---|---|
| 聊天 | `!ze` / `!zemenu` | 打开主菜单 |
| 聊天 | `!ze_ui` | 打开 / 关闭当前功能菜单 |
| 聊天 | `!0`、`!9`、`!ze_ui_close` | 关闭功能面板，取消排队请求并释放鼠标捕获 |
| 聊天 | `!1`–`!6` | 选择当前页项目 |
| 聊天 | `!7` / `!8` | 上一页 / 下一页 |
| 聊天 | `!ze_ui_chat` | 本连接改用聊天菜单 |
| 聊天 | `!ze_ui_ready` | 恢复右侧菜单模式 |
| 聊天 | `!ze_ui_status` | 本人菜单状态、资源和失败原因 |
| 无线电输入菜单激活时 | 数字键 `9` | 关闭右侧面板；现有工坊输入表随后返回原生无线电主页 |

**区别：**未额外绑定的键盘 `0` 是引擎本地“退出无线电输入”，不会自动通知服务端关闭自定义面板。聊天 `!0` 是服务端完整关闭指令。原生左侧输入层仍可用 `0` 收起。本次不替换全局 HUD、不注入客户端 JS、不改玩家键位，也不承诺已经实测所有客户端的原生按键转发。

执行功能后继续保留窗口和页码。换图/断线/卸载时清理会话。原有 1.7.6 预定清理、服主VPK直切、RTV和1.7.5指挥倒计时不变；不改地图脚本、模型、手模、MAM或CS2Fixes。
