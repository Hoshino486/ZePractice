# HUD 与地图脚本诊断修复（2026-10-16 / ZePractice 1.7.2）

## “未提供 ScriptOnTick”究竟缺了什么

不需要服主或玩家提供任何脚本、文件或配置。

旧实现只查找 VProf 中名字为 `ScriptOnTick` 的计数器。实际服务器只有 4 个既有计数器，没有这一项；当前 Windows 引擎二进制也没有这个字符串。因此旧显示只代表该计数器没有数据，**不代表地图脚本没有执行**。

现在移除这一过时显示，直接只读观测引擎真正调用服务器 JS 回调的入口。没有修改地图脚本，没有更改回调参数、返回值或调度。

## 新界面与公开指令

`!ze_diag` 开关面板；`!ze_script_status` 查看脚本活动。后者也在公开功能菜单里，无额外权限。

| 字段 | 实际含义 |
|---|---|
| 脚本实体 | 当前有效的 `point_script` 实体数；不是脚本文件数，也不等于成功加载数 |
| 活动上下文 | 最近采样窗中实际执行过回调的不同 JS 上下文数 |
| 回调 N/s | 真实完成的回调次数除以实际采样窗时长 |
| Think N/s | 回调中名为 `Think` 的子集；不要与回调总量相加 |
| 异常 N（累计 M） | 当前窗和本次地图/采样器启动以来被 V8 捕获的回调异常 |
| 本窗无回调 | 此窗口没观察到执行；事件型脚本可能只是在等事件，不能据此判定损坏或加载成功 |
| 采样接口未就绪 | 采样器自身未就绪，例如游戏更新导致二进制校验不匹配；不会用假 0 冒充正常 |

诊断每半秒更新一次。热重载插件和换图会开始新的统计周期。

服务器控制台 `css_ze_script_status` 额外返回实际窗长、原始计数、未知返回值数、最后一次活动距今多久和外层回调墙钟耗时。耗时去除了嵌套调用的重复计算，但包含原生函数和观察器开销，不是纯 JS CPU 时间。

该观察器不覆盖脚本启动阶段的导入/编译错误，不声称自动证明地图所有传送、技能、伤害等业务逻辑正确。具体异常文本仍保留在引擎日志。

## 原 HUD 不显示的真正根因

实际客户端日志明确报错：

```text
[custom_hud] Layout contains disallowed attribute hittestchildren for panel type 'Panel'.
[custom_hud] Layout xml did not pass CustomHud validation
```

普通资源编译通过，不代表 CS2 CustomHud 运行时会接受布局。已删除 movement/diagnostics 中不受支持的 `hittestchildren` 和主菜单 Button 的 `hittest`，并在构建前加入 Valve CustomHud 元素/属性白名单校验。

本轮前半段已使用真实游戏客户端验证个人移动 HUD、诊断 HUD 的开关和与菜单共存，截图位于 `artifacts/hud-client-validation-20261016/workshop-{off,on,menu}.png`。这些旧截图仍保留旧版 ScriptOnTick 字样；本轮最终脚本界面截图以 `artifacts/script-diagnostics-20261016` 下的新验收结果为准。
