# HUD 与个人练习 Bot 修复 — ZePractice 1.7.1

日期：2026-10-16。对应反馈：菜单显示个人参数和服务器诊断均已开启，但画面不显示；个人 Bot 不能正常站立持枪。

## 本次改动

### 1. 个人参数和服务器诊断 HUD

- 两个 `custom_hud_layout` 的实际加载名统一为编译资源 `movement.vxml_c` / `diagnostics.vxml_c`，与资源校验、预缓存、实际 VPK 成员及已经正常显示的 radio 菜单一致。旧版只检查了服务端布局实体，错误地把 `.vxml` 字符串当成正确加载契约。
- 使用与现有 radio 相同的显示方式：全局默认隐藏、目标玩家的网络布局状态显式取消隐藏；保留 CheckTransmit 个人过滤。关闭一人的诊断不会关闭其他人的共享诊断面板。
- 移动面板资源刷新时先清理旧实体，避免重建后留下无人管理的布局。
- 不占用地图神器中心提示，不捕获鼠标/键盘，不修改地图脚本。个人参数仍为 10Hz，服务器诊断为 2Hz。

### 2. 个人 Bot 的物理、持枪与输入控制

- 保留 `CCSPlayerPawn.BotAllowActive` 与 `CCSBot.AllowActive`。旧版同时关闭这两个入口，隔离服实测离地后不下落。
- 不使用 `FL_FROZEN` 实现站桩：对照测试证实，虽然这种做法能落地，冻结角色会被引擎免除伤害，已淘汰该候选。
- 最终方案在原生 `CCSBot::Update` 执行后，仅对当前注册的个人练习 Bot 清除主动移动/攻击输入。原始 AI 更新、用户命令模拟、重力、落地、武器和受伤流程继续执行。不修改全服 `bot_stop` 或 `bot_dont_shoot`。
- 原生入口验证：Windows x64 CS2 1.41.9.1 / build 2000932，Update RVA `0x2e2120`；校验整个 server.dll SHA-256 和唯一指令签名后才安装。游戏版本变更导致验证失败时，不创建失控 Bot，状态接口给出未就绪。
- 练习 CT Bot 正常发放 M4A4（引擎类名 `weapon_m4a1`），练习 T Bot 正常发放 AK-47，并走引擎原生装备流程，而非额外摆放假人模型。
- 练习 Bot 在底层的 CanUse / CanAcquire / GiveNamedItem / EquipWeapon 僵尸武器拦截中被精确排除。**真人僵尸及非个人练习 Bot 的原禁枪规则保持不变。**
- 保留个人数量限制、服主例外、血量预设、所有权隔离、死亡删除、伤害/减速统计及不回血。
- 未修改卢娜的骨骼、模型、材质、动画资源或地图脚本。
