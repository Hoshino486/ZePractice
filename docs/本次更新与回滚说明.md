## 4. 游戏验证完整性之后怎么恢复

### 4.1 只恢复本次客户端 UI 和快捷键

首先确认客户端正常安装路径没有改变。当前可用的编译资源包保存在：

```text

```

本说明写入时，安装脚本确实存在于源码 `tools`，编译资源确实存在于上述构建目录；不假定尚未复制到部署目录的文件已经存在。

在 PowerShell 执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\34184\Documents\ChatGPT\CS2脚本\ZePractice\tools\Install-ZeClient.ps1" -ClientGameRoot "D:\SteamLibrary\steamapps\common\Counter-Strike Global Offensive 730\game" -AssetsRoot "E:\mapper\chana\临时文件夹\ze-ui-access-20261011\build\ze_practice_ui"
```

这个命令会进行安装和备份，**不是只读预览**，但它不会启动游戏、改 gameinfo、登录 Steam 或发布 Workshop。

安装输出应显示 `Status=Installed`，并返回这一轮新的 `Manifest` 路径。把新路径保存下来。已有相同内容时不必重复覆盖不同文件；遇到用户改动/资源错误会按脚本校验处理。

然后重新启动客户端，或客户端控制台执行 `exec ze_practice_keys`。进服后打开菜单测试。界面异常时先输入：


这次 UI/快捷键恢复路径不需要修改 gameinfo，也没有“把旧文件覆盖回去”的步骤。

如果 Steam 更新后是 **Metamod/框架没有加载、服务端启动失败、引擎插件 API 不兼容**，那是另外的故障类型：先看当前官方文件、插件加载和日志，按原服务器修复流程处理。重新安装这四个客户端文件不能代替服务端插件适配，也不要用旧 gameinfo 把新版引擎指向已经不存在的 `csgo_imported`。

## 6. 如何回滚

### 6.1 只是不喜欢图形界面，不必回滚整个插件

当前连接输入：

```text
css_ze_ui_close
css_ze_ui_chat
```

即可关闭图形并使用聊天菜单。想全服长期使用聊天菜单，可在主插件 JSON 把 `MenuUiMode` 改成 `chat`，按主插件配置加载方式重载插件/重开服务；这不影响自定义权限和普通聊天指令。

`!ze_permissions_reload` 只重载权限，不重读这个主 JSON；`!ze_reload` 是地图相关配置重读，也不是 UI 主配置重载。

### 6.2 回滚本次客户端四个文件

已核对的本次客户端安装清单：

```text
E:\mapper\chana\临时文件夹\ze-ui-access-20261011\client-backups\20261011-190514-755-7e1cd025c91a447c80c910ab861d006e\manifest.json
```

本次清单记录：两个 UI 文件和 `ze_practice_keys.cfg` 原来不存在，autoexec 原来存在且已备份。回滚会按记录恢复/移除这四个已管理文件，不递归删除整个 cfg 或 panorama 目录。

执行以下命令前，保存后来手工改过的 cfg。然后运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\34184\Documents\ChatGPT\CS2脚本\ZePractice\tools\Install-ZeClient.ps1" -RestoreManifest "E:\mapper\chana\临时文件夹\ze-ui-access-20261011\client-backups\20261011-190514-755-7e1cd025c91a447c80c910ab861d006e\manifest.json"
```

这是实际恢复命令，不是查看清单。恢复逻辑：

1. 验证产品/清单格式、确切客户端目录与四个允许路径。
2. 验证原文件备份是否仍存在、内容是否匹配。
3. 当前文件仍等于当时安装版本，才恢复原文件或移除当时新增文件。
4. 安装后又被用户改动的文件不会被盲目覆盖，返回冲突项；可能是 `PartiallyRestored`，需要逐项处理，不可当完整成功。
5. 后续重复安装会生成新清单。要回到初次安装前，按实际版本顺序回滚，不要不看文件状态就混用清单。

**文件恢复不等于已经执行的按键状态倒带。** 安装器没有记录或读取 Steam userdata 内原六个键的绑定，所以它不会替用户猜测原用途。

如果已经执行过新的 bind，回滚后在客户端控制台查询：

```text
bind ALT
bind F9
bind F11
bind INS
bind HOME
bind END
```

有旧配置的，按自己的旧配置恢复。某个键原来确实没有用途时，才 `unbind` 那个键；不要整体清空键位。旧 FYS ALT 若本来就是 `noclip`，可按原记录重新绑定 `noclip`；其余原用途不在本文臆造。F5/F7/F8 没有被本次改动，不需要为本次回滚重写。

### 6.3 回滚服务端插件到部署前版本

部署前备份根：

```text
E:\mapper\chana\临时文件夹\ze-ui-access-20261011\deployment-before
```

| 备份文件 | 恢复到 |

1. 通知在线玩家，正常关服并确认目标专用服务器进程退出，再替换 DLL；不要边运行边覆盖框架组件。

服务端回滚没有执行在本说明编写期间；以上是保留数据的手工步骤，不宣称已经回滚。
