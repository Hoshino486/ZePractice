# 菜单执行后保持打开（2026-10-17 / ZePractice 1.7.3）

## 已实现的行为

- 公开指令及由插件统一打开的功能菜单选择后不再自动关闭，也不自动跳回首页。
- 无线电菜单保留原来的 `custom_hud_layout` 实体和当前页。开关状态在原位置刷新；鼠标面板、聊天降级菜单也保留当前页。
- 状态查询、Bot 添加/移动/删除、数值预设可以连续操作；原指令权限、调用者身份、人数限制及输入范围不变。
- 自定义聊天数值输入开始、成功、取消均不主动关闭或重开窗口。数值输入本身仍只在 60 秒内有效。
- 移除无线电界面的 115 秒闲置自动关闭。已确认可见的鼠标面板也不再两分钟自动关闭。
- 主动关闭取消待打开的菜单；待处理的选择与状态刷新只作用于同一个有效会话，不会重新打开已关闭界面，也不会覆盖新的子菜单。
- 换图、断线、插件卸载、权限失效仍会清理旧会话。鼠标面板尚未确认可见时仍保留原来的 20 秒聊天降级，以免不可见界面占用输入。

关闭方法：菜单 **9 关闭**、原有绑定的 **0 退出**，或聊天 `!ze_ui_close`。子菜单中的“返回公开指令”仍是显式导航到首页，不等同于执行普通功能。

## 原因与实现

原公开菜单使用 `PostSelectAction.Close`，无线电适配器又在任何选择前删除布局。部分开关随后延迟调用 `ShowMenu`，导致自动重开首页，并存在手动关闭后被延迟任务重开的情况。

- `src/PersistentChatMenu.cs`：动态标签在既有选项上刷新；聊天降级刷新绑定同一个菜单实例、用户 ID 和控制器序列。
- `src/PublicGameplayService.Menus.cs`：去除延迟无条件重开首页和数值输入主动关闭；读取当前个人开关生成动态标签。
- `src/RadioPanelService.cs`：保留实体/页码，延迟刷新检查当前会话和待导航请求；移除闲置截止时间。
- `src/ZePanelService.cs`：执行普通操作保留会话，显式导航才更换布局；关闭后释放鼠标捕获；保留旧页面点击序列隔离。
- `src/ZePracticePlugin.Access.cs`：统一菜单选择策略为保持打开，保留关闭入口；命令仍以原玩家身份执行。

没有修改地图脚本、模型、HUD XML/CSS、客户端绑定或工坊 VPK。
